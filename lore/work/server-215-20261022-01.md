# 172.20.12.215: lore-auth-bridge Service Account 対応版への更新

`172.20.12.215` の `lore-auth-bridge` を Service Account 対応 revision へ更新するための
標準手順と、2026-10-22 の稼働確認記録である。

## 適用内容

- source revision:
  [`lore-auth-bridge` commit `ee81aa6`](https://github.com/radicalgrimoire/lore-auth-bridge/commit/ee81aa6)
  (`Add service account authentication`)
- 更新した binaries:
  - `/opt/lore/bin/lore-auth-server`
  - `/opt/lore/bin/lore-authctl`
- service:
  `lore-auth.service`

215 の `/home/mgs/src/lore-auth-bridge` は `ee81aa6` で clean であり、稼働 binary と
同じ revision を指している。

## source からの標準適用手順

215 では `/home/mgs/src/lore-auth-bridge` を build source とする。作業開始前に source
tree が clean であることを確認し、適用する revision を明示的に checkout する。

```bash
cd /home/mgs/src/lore-auth-bridge
git fetch --prune origin
git status --short
git checkout --detach ee81aa6a1ab4e79d63a91db7a1a830706cf06b11
git status --short

source "$HOME/.cargo/env"
cargo build --release -p lore-auth-server -p lore-authctl
```

更新前の binary を archive してから、build output を配置する。`lore-auth` 以外の service
は restart しない。

```bash
STAMP="$(date -u +%Y%m%dT%H%M%SZ)-service-account"
ARCHIVE="/opt/lore/archive/$STAMP"
sudo install -d -o root -g root -m 0700 "$ARCHIVE"
sudo cp -p /opt/lore/bin/lore-auth-server /opt/lore/bin/lore-authctl "$ARCHIVE/"
sudo sh -c "sha256sum '$ARCHIVE/lore-auth-server' '$ARCHIVE/lore-authctl' \
  > '$ARCHIVE/SHA256SUMS'"

sudo install -o root -g root -m 0755 \
  target/release/lore-auth-server /opt/lore/bin/lore-auth-server
sudo install -o root -g root -m 0755 \
  target/release/lore-authctl /opt/lore/bin/lore-authctl
sudo systemctl restart lore-auth
```

## rollback archive

更新前の binaries は次の archive に保存した。

```text
/opt/lore/archive/20261022T045441Z-service-account
```

rollback が必要な場合は、service を停止して archive 内の二つの binary を
`/opt/lore/bin/` に戻し、`lore-auth` を restart する。SQLite migration は
backward-compatible な `service_accounts` table の追加であり、この更新で既存の
identity / group / grant data は変更していない。

## 実施した確認

```bash
sudo systemctl is-active lore-auth
/opt/lore/bin/lore-authctl service-account --help
curl --fail http://127.0.0.1:18080/healthz
curl --fail http://127.0.0.1:18080/.well-known/jwks.json
sudo ss -ltnp | grep -E ':(18080|18081)\b'
curl --insecure --fail https://172.20.12.215:8080/healthz
```

結果:

- `lore-auth` は `active`。
- `lore-authctl service-account` に `add` と `rotate` が表示される。
- bridge health endpoint は `ok`。
- JWKS は正常に応答した。
- HTTP listener `127.0.0.1:18080` と gRPC listener `127.0.0.1:18081` は正常。
- public nginx proxy 経由の health endpoint は `ok`。
- SQLite database
  `/datadrive/lore/auth/data/lore-auth.sqlite3` に `service_accounts` table が作成された。

## 未実施の後続作業

今回の更新では Service Account をまだ作成していない。次に実施する際は以下を行う。

1. 215 用 TLS certificate と private key の作成・配置。
2. CI runner の Local Machine trust store への public certificate の追加。
3. 用途を反映した client ID で Service Account を作成し、secret を Jenkins credential
   store に登録。
4. runner source CIDR と repository role grant を group 経由で付与。
5. nginx gRPC location へ `x-lore-client-ip` forwarding を設定。
6. Jenkins から `service-account` token exchange、clone、必要なら専用 repository
   への commit / push を検証。
