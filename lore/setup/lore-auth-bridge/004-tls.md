# TLS certificate の作成

[構築手順と前提](README.md) を確認する。一般化した手順は別環境で通し検証していない。

社内 IP / plaintext の実機では `CA:FALSE` の自己署名 server certificate を使用した。
この証明書は Lore QUIC、nginx HTTPS と bridge gRPC に必要であり、Lore gRPC が
平文でも不要にはならない。以下は自己署名の例である。

DNS / TLS では DNS 名と内部接続先を SAN に含む CA 発行証明書と chain を用意し、
信頼する CA を配布する。以下の自己署名生成は使わず、
[TLS 版の証明書と接続](../../work/lore-tls/README.md#証明書と接続) を参照する。
`/opt/lore/certs/lore-server.crt`、`.key` と CA 証明書
`/opt/lore/certs/lore-ca.crt` にそれぞれ配置し、service user と nginx に必要な
読み取り権限を与える。既存の証明書・鍵は上書きしない。

社内 IP / plaintext の場合は、次の 2 行を自環境の値に編集する。
IP の例は `SERVER_SAN='IP:192.0.2.10'`。`SERVER_HOST` と SAN は一致させる。
新規環境専用。配置先の証明書と鍵が既に存在する場合は実行しない。

```bash
SERVER_HOST='<SERVER_HOST>'
SERVER_SAN='<IP:address または DNS:hostname>'
WORKDIR="$(mktemp -d)"
trap 'rm -rf "$WORKDIR"' EXIT

openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 365 \
  -subj "/CN=$SERVER_HOST" \
  -addext "basicConstraints=critical,CA:FALSE" \
  -addext "keyUsage=critical,digitalSignature,keyEncipherment" \
  -addext "extendedKeyUsage=serverAuth" \
  -addext "subjectAltName=$SERVER_SAN,DNS:localhost,IP:127.0.0.1" \
  -keyout "$WORKDIR/lore-server.key" \
  -out "$WORKDIR/lore-server.crt"

sudo install -o root -g lore -m 0644 \
  "$WORKDIR/lore-server.crt" /opt/lore/certs/lore-server.crt
sudo install -o root -g lore -m 0640 \
  "$WORKDIR/lore-server.key" /opt/lore/certs/lore-server.key
openssl x509 -in /opt/lore/certs/lore-server.crt -noout \
  -subject -issuer -dates -fingerprint -sha256 -ext subjectAltName
```

subject、SAN、有効期限、fingerprint を確認する。private key は server 外に配布しない。
